# SSR2Clash 单订阅服务与桌面界面重做设计

日期：2026-10-16

分支：`codex/subscription-server-upgrade`

开发基线：远端 `main` 的 `71caca2b0b87457763c70411b8c131b6365388c6`

状态：主体设计已获用户允许继续；补充图标方向，实施计划待审阅；尚未实施产品代码。

## 1. 目标与已确认需求

把当前一次性 SSR 转换器升级为可长期运行的 Windows 桌面订阅工具。

用户已经确认：

- 第一版管理一个原订阅，生成一个稳定的本地订阅链接。
- 输出效果参照 tindy2013/subconverter，提供完整 Clash YAML、策略组和分流规则。
- 用户不需要研究或编写模板才能获得上述默认效果。
- 实时模式下，Clash 每次请求本地订阅，都重新拉取原订阅并转换。
- 快照模式下，本地订阅请求直接获得之前保存的 YAML，不拉取原订阅。
- 增加可开关的开机自启功能。
- 整体重做 UI，并升级依赖。
- 同时提供 Windows 便携版和可安装版。
- 可安装版允许用户自行选择安装路径。
- 更换应用图标，并评估名称；当前建议保留 SSR2Clash，增加中文功能说明。
- 页面采用现代桌面工具风；用户明确否定绿色主题，改用银灰与钴蓝方向。
- 在从最新 main 新建的迭代分支上工作。

本提案采用的产品默认值：仅本机访问、关闭窗口收进托盘、明确退出才结束服务；快照跨重启保留；实时更新失败时回退同一份配置最近成功的结果。用户审阅时可调整这些默认值。

## 2. 实现路线

采用原生 Rust 转换核心，Tauri 窗口命令和本地 HTTP 服务共用同一条处理链。

相比附带 subconverter 可执行文件，这条路线让便携版和可安装版共用一个应用核心，减少额外进程的启动和打包管理。相比全面复刻 subconverter，范围集中在本项目的 SSR 输入、Clash 输出和常用分组规则配置。

“效果对齐”以策略组成员、引用关系和分流顺序为准，不要求 YAML 的缩进、注释、字段排列逐字相同。原始 SSR 节点仍然是 SSR，不把协议转换成 SS 或其他协议。

第一版支持内置默认预设；保留常见 INI 分组／规则配置的导入入口作为高级功能。支持 `custom_proxy_group`、`ruleset`、对应的生成开关和 `!!import`；脚本执行、通用模板语言及其他客户端输出不属于本次验收。遇到影响输出的未知配置，给出具体错误，不能静默丢掉后继续声称转换成功。

## 3. 现有代码需要解决的问题

- `ClashConfig` 没有 `proxy-groups` 和 `rules`，当前 `mode: rule` 的输出缺少完整策略。
- SSR 的 `group` 已被解析，但转换时没有参与分组。
- `obfs_param`、`protocol_param` 当前直接以 Rust 字段名输出，需要序列化为 `obfs-param`、`protocol-param`。
- 订阅获取、外层 Base64 解码和节点预览在 React 页面中，后台服务无法复用。
- 节点数通过匹配 YAML 中的 `- name:` 统计，加入策略组后会把组也算进去。
- 当前解析器只覆盖有限的 Base64 形式，解析测试存在空用例。
- 没有持久化配置、快照、服务生命周期、托盘和开机自启管理。
- `serde_yaml` 已停止维护；前后端 Tauri 依赖和构建工具需要统一升级与锁定。

## 4. 转换核心与默认输出

### 4.1 输入处理

Rust 负责获取原订阅、判断明文 SSR 列表或 Base64 包装、解析节点、过滤、生成分组规则和序列化 YAML。支持标准／URL-safe Base64 及有无 padding 的常见形式，中文名称通过 UTF-8 正确解码。

当前包含、排除关键词功能保留。转换结果通过结构化数据返回节点数、组数、无效节点数、警告、生成时间及 YAML，不在前端重新解析文本统计。

无效节点可跳过并报告数量；没有有效节点或过滤后为空时视为失败，不覆盖已有成功结果。重复或空白节点名生成稳定、唯一的名称，组引用使用最终名称。

### 4.2 默认分组与规则

以 upstream 的 `base/pref.example.ini`、`base/snippets/groups.txt`、`base/snippets/rulesets.txt` 及其引用的规则资源作为默认预设的来源。

默认组覆盖节点选择、自动选择、国外媒体、国内媒体、微软服务、电报信息、苹果服务、全球直连、全球拦截和漏网之鱼；保持 upstream 未注释配置的成员关系与顺序。输出包含 `proxies`、`proxy-groups`、`rules`，将 FINAL 按 Clash 语义转为 MATCH，并保持最终兜底规则在末尾。

默认资源随应用提供。实现时记录实际采用的 upstream commit、资源路径及许可证，生成可复现的验收样本；用户运行应用时不依赖 GitHub 可达。默认资源通过应用版本更新，不在每次本地订阅请求时隐式更新。

输出采用标准 Clash／Mihomo 字段；保留安全的本机监听默认值。对组引用不存在、空测速组、循环组引用、重名组、无效正则或不支持的规则类型，返回明确错误。默认预设中能通过 DIRECT 或有效组提供候选项的选择组允许没有匹配到特定地区节点。

### 4.3 高级 INI 导入

支持本地文件和 HTTP(S) 地址。INI 解析必须保留重复键和声明顺序。分组支持 `select`、`url-test`、`fallback`、`load-balance`，节点正则筛选、`[]` 显式引用，以及按 SSR 原始 group 匹配；规则支持直接声明和内联展开的远程列表。

`clash_rule_base` 支持普通 YAML 基础配置，以正确实现启用／关闭规则生成及覆盖／追加原规则的开关。基础配置中的非节点选项保留；代理节点由当前订阅替换，分组和规则按 INI 的明确配置生成。脚本与模板语言仍不执行。

导入资源的相对路径按所属配置文件或 URL 解析；文件读取限制在用户选择的配置目录。远程配置不能借助本地路径读取用户文件。限制导入深度、总大小并检测引用循环。正则支持范围须覆盖所提供的默认预设和用户导入的验收样本；不支持的表达式必须指出原始配置行。

切换到自定义预设后，实时刷新同时获取该配置及其必要的远程规则；任一必要资源失败时，整次生成失败，不发布缺规则的半成品。快照订阅响应不读取或刷新这些资源。

## 5. 本地订阅服务

服务使用 Axum，在 Tauri 管理的异步运行环境内运行。监听 `127.0.0.1`，默认端口 `25501`，允许用户修改端口。端口被占用时显示明确错误，不自动换端口导致现有 Clash 订阅地址失效。

首次保存配置时生成并持久化随机令牌，订阅地址形如：

`http://127.0.0.1:25501/sub/<token>.yaml`

原订阅地址不出现在本地订阅 URL 中。重复启动、停止、开机自启和应用升级保持令牌与端口稳定；用户明确更改端口或重置令牌时提示需更新 Clash 中的地址。

- `GET /sub/<token>.yaml`：提供订阅内容。
- `HEAD /sub/<token>.yaml`：返回当前可用结果的响应头，不触发上游拉取。
- `GET /health`：仅报告进程与服务是否正常，不暴露订阅内容或地址。

成功响应为 UTF-8 YAML，设置正确的 Content-Type、Content-Disposition 和 `Cache-Control: no-store`。不设置通用跨域读取权限；订阅令牌无效时返回 404。HTTP 入口不提供修改配置或读取任意文件的能力。

### 5.1 实时模式

每个有效 GET 请求独立执行一次上游刷新，不使用时间缓存跳过原订阅拉取，也不把并发请求合并成一次刷新。初始上游超时设为 20 秒，单次失败不额外自动重试；Clash 的后续请求仍可再次触发刷新。

并发刷新最多 2 个，超出时返回 503 和 Retry-After，避免无限排队。后台拉取不占用主界面线程。

生成成功后，验证引用与基本配置结构，再持久化 YAML 和元数据，最后更新 UI。失败时：若存在当前配置版本对应的最近成功结果，返回该 YAML，并记录本次失败、旧结果的生成时间及回退状态；没有可用结果则返回 502。错误内容不能冒充 YAML 以 200 返回。

下载请求默认直连，并在高级设置提供“使用系统代理”选项。默认避免订阅刷新依赖正在更新的 Clash 代理链。

### 5.2 快照模式

最近成功结果与冻结快照使用不同的持久化记录。开启快照时，把当前成功 YAML 固定为冻结快照；没有当前有效结果时，不允许开启，并提示先生成一次。

快照模式的每次 GET 返回同一份已保存的 YAML 字节，不请求上游、不重新执行分组、不更新生成时间。关闭快照后，下一个 GET 恢复实时拉取。

快照模式禁用影响输出的配置编辑。用户需要先关闭快照再修改原订阅、过滤规则或预设；设置开机自启、界面主题等不影响输出的选项仍然可用。冻结模式第一版不提供隐式后台刷新或自动替换快照。

### 5.3 配置变更与请求竞态

每次影响输出的配置变更增加配置版本。源地址、过滤或预设变化后，旧版本的成功结果不能作为新版本的回退数据。执行中的请求使用开始时的配置副本；旧版本请求完成后不能覆盖新配置对应的持久化结果。

切换到快照或停止服务后，未完成的实时任务不得替换冻结快照或继续发布为当前结果。停止服务执行有界取消，释放监听端口；再次启动不残留旧任务或重复监听。

## 6. 持久化与桌面生命周期

便携版通过 exe 同目录的 `portable.flag` 标识，在该目录的 `data/` 中保存配置和结果；安装版保存在 Tauri 应用数据目录。启动时先确定数据目录，再初始化配置、令牌、服务与快照。便携目录不可写时显示具体路径和失败原因，不静默改用另一份数据目录。

数据包含格式版本，升级时保留源地址、本地端口、令牌和可读取的快照。写入采用临时文件加替换，并在 Windows 验证覆盖已有文件的行为。磁盘写入失败时不宣称“已保存”或“快照已开启”。

持久化数据分为配置、最近成功结果、冻结快照及各自的生成时间／配置版本。避免把真实订阅地址、凭证或完整 YAML 写入运行日志。

采用单实例运行；再次打开软件只显示已有窗口，避免端口重复绑定。便携版和安装版也遵循同一单实例约束；检测到另一种分发方式已运行时说明当前运行路径，不让用户误以为已打开另一份配置。

- 首次启动：开机自启关闭、本地服务关闭，等待用户填写订阅。
- 用户开启服务：保存开启意图；后续启动恢复服务。用户手动停止后保存关闭意图，重启不擅自重开。
- 关闭主窗口：默认隐藏到托盘，原有服务继续工作；托盘提供打开窗口、启动／停止服务、退出。关闭“关闭窗口留托盘”设置后，关窗执行与明确退出相同的停止流程。
- 开机自启：使用 Tauri autostart 插件，登录 Windows 后以托盘方式启动，恢复服务开启意图与快照模式。登录前的 Windows 系统服务不在本轮范围内。
- 开机网络未就绪：服务仍可监听；快照可立即返回，实时请求按通常失败与回退规则处理。
- 退出：停止监听并结束应用。自启开关注册失败时回显真实错误，并按系统实际注册状态显示。

Windows x64 是本轮功能验收平台；不把未运行的其他系统行为标记为已验证。

## 7. UI 整体重做

采用现代桌面工具风：浅色使用银灰与白色表面、深墨色文字、钴蓝 `#3869F5` 主强调色；深色使用石墨灰表面与蓝色点缀。提供浅色／深色／跟随系统三种主题。用户已否定先前的深青／薄荷绿色方向，绿色不再作为界面或品牌主色。

页面的现代感通过明确的信息主次、紧凑工具栏、足够的留白、统一的细边框和字体层级建立。主体采用宽结果区加窄服务检查区的非对称布局，原订阅输入置于顶部完整一行；服务状态始终可见。避免把每一项信息都包装成大卡片、把所有区域做成等宽方块，或用超大标题挤占实际操作空间。沿用 React、Tailwind、Radix 的可访问交互基础，重新设计页面布局与业务组件。

主界面按使用顺序组织：

1. 顶栏：应用名称、服务状态与主题／设置入口。
2. 订阅区：原订阅地址、包含／排除关键词、默认或自定义预设，以及保存设置和立即生成动作。
3. 本地服务区：实时／快照切换、启动／停止、固定本地链接和复制按钮；同时说明当前模式对应的刷新行为。
4. 结果区：节点数、策略组数、最近成功时间、最近请求时间与回退提示；切换查看节点列表、策略组和完整 YAML，并保留复制与导出。
5. 调试区：默认折叠的有限运行记录、解码内容及无效节点信息。

开机自启、关闭窗口留托盘、服务端口、获取订阅的代理方式和高级 INI 导入放入设置；常用服务状态与快照开关在主界面直接可见。

初次使用、生成中、服务停止、端口占用、拉取失败但有旧结果、没有结果、快照已冻结都提供相应状态和可执行动作。不要只依靠瞬时 toast 或颜色解释错误。

最低目标窗口为 1000×700，默认窗口 1200×800；较窄时按单列自然滚动。中文标签完整可读，按钮键盘可操作；长地址和 YAML 在自身区域滚动，不把窗口撑宽。

### 7.1 名称与图标

建议显示名称使用 `SSR2Clash`，主界面副标题使用“订阅转换与本地托管”。Cargo／npm 包名、exe 文件名及应用标识符 `com.redpandaex.ssr2clash` 保持既有身份；本轮不另起品牌名称。

图标采用原创的几何连接图形：两端节点由一条平滑流线连接，表达原订阅经转换后在本机提供服务。应用图标改用石墨底色、白色与蓝色图形，不嵌入文字；托盘图标采用对应的单色透明版本，检查 16／24／32 像素可读性。矢量草案、图标预览和页面概念稿放在 `docs/superpowers/assets/`，供用户审阅。

浅色主界面概念稿：`../assets/ssr2clash-workbench-light-concept.png`；该图用于确认视觉方向，实际界面通过 React 实现。名称和图标以 SVG 源及本节说明为准，生成图中的小图形仅作界面位置参考。

实施时使用同一份 SVG 源通过 Tauri icon CLI 生成平台资源，并更新主界面、窗口、任务栏、托盘、安装器和快捷方式所用图标。不能只替换界面中的一张图片而保留打包资源里的默认图标。

## 8. 模块边界

- `subscription`：HTTP 获取、输入识别及结构化结果，不依赖窗口。
- `ssr`：解析与过滤纯逻辑，保留现有模块并补齐边界。
- `preset`：内置默认资源、常用 INI 导入、组与规则生成及校验。
- `conversion`：组织完整转换流水线，供手动转换与 HTTP 请求复用。
- `storage`：带版本的设置、最近成功结果、冻结快照与持久化。
- `server`：路由、响应、并发边界、启动停止，不重复编写转换逻辑。
- `desktop`：托盘、单实例、自启与窗口生命周期。
- 前端：通过类型化 Tauri API 获取状态、提交动作；监听后台状态事件后重新读取当前状态，不依赖保留的网页内存。

## 9. 依赖与双版本交付

### 9.1 依赖升级

保持 Tauri 2、React 19、Tailwind 4 技术路线。构建工具迁移到受支持的 Vite 8 稳定版本并同步匹配 React 插件；TypeScript、Biome、Tauri JS／Rust 插件按兼容组合升级，实际解析版本锁在 lockfile 中。

Rust 增加 Axum、所需的 Tokio／HTTP 客户端直接依赖，以及 autostart、single-instance 插件；YAML 迁移到 serde-saphyr，对本项目用到的序列化和反序列化行为建立回归。移除替代后确实不再使用的插件与权限。

依赖变更通过 pnpm／Tauri／Cargo 官方 CLI 完成。核对本机运行的 pnpm 与 packageManager 声明，避免当前环境中构建命令隐式尝试重装依赖的问题。CI 固定 pnpm 版本，Node 运行环境与类型定义保持一致，执行前后端检查后再打包。

### 9.2 便携版

提供 `ssr2clash_<version>_windows_x64_portable.zip`，解压后包含 `ssr2clash.exe`、`portable.flag` 和使用说明。`data/` 在第一次运行时创建，分发包不包含用户订阅或预生成令牌。

无需安装，配置与快照随整个文件夹携带。覆盖升级时只替换应用文件，保留原 `data/`。移动时应移动整个目录；开机自启记录实际 exe 路径，移动后可在设置中重新注册。

便携版依赖系统已有 WebView2 Runtime；缺少时在使用说明中给出官方安装入口，不把“免安装”描述为无需运行环境。

### 9.3 可安装版

提供 NSIS 安装包 `ssr2clash_<version>_windows_x64_setup.exe`，采用当前用户安装方式，提供开始菜单入口与卸载入口。应用功能、版本和默认规则与同次构建的便携版一致。

正常交互安装必须显示“选择安装位置”页面，允许修改默认目录，选择其他盘符或有写入权限的文件夹。支持包含中文、空格的路径；目录不可写时在安装前给出明确提示。覆盖升级默认沿用上一次的安装目录；快捷方式、卸载入口和开机自启均使用实际安装路径，不能硬编码到 C 盘或默认目录。

安装目录和数据目录分离。覆盖升级保留原配置、端口、令牌、快照和自启设置；更新已运行的应用前要求结束当前进程。安装包在缺少 WebView2 时按 Tauri 的引导安装机制处理，正常情况下复用已有 Runtime。

卸载默认保留用户数据，只有用户明确选择清理时才删除；清除属于当前安装路径的自启项，避免卸载后残留失效入口。不得误删另一份便携目录的数据或自启注册。

两种分发方式的数据目录各自独立，第一版不自动迁移两者的数据。设置界面展示当前数据目录与运行方式，便于区分。只有同一份数据保留或被显式迁移时，才保证原来的订阅令牌与本地链接延续。

### 9.4 构建与发布边界

更新 Tauri 打包配置与现有 Windows CI，从同一提交、同一版本号同时产出便携 ZIP 和 NSIS 安装包。工作流检查两个文件均存在且非空，再将两者作为构建产物归档；后续执行发布时，两种包应一同出现在该版本的下载项中。

本轮实际构建并验证这两种包；未经用户进一步要求，不创建发布标签或发布 release。

## 10. 验收与验证

### 转换与默认效果

- 使用虚构 SSR 样本覆盖中文名称、Base64 变体、重复名称、无效节点和空过滤结果。
- 输出能被 YAML 解析，SSR 字段名正确，组成员与规则目标均存在，节点数量不会包含策略组。
- 同一组虚构节点分别由固定版本 subconverter 和本项目处理，比对默认组成员、顺序、内联规则和兜底语义；比较范围与 upstream commit 随样本记录。
- 常用 INI 的重复键、组引用、相对导入、远程规则、循环引用与错误提示有实际测试。

### 本地服务与快照

- 用可计数的本地假上游测试：每个实时 GET 都产生一次上游获取；重复快照 GET 为零次获取且响应字节相同。
- 验证上游超时、错误内容、空节点、磁盘写入失败、同版本回退与无缓存错误状态。
- 重启后订阅 URL、服务开启意图和快照保持；修改配置、并发请求、模式切换与停止服务不会让旧任务覆盖新状态。
- 验证端口占用、无效令牌、请求并发上限、HEAD 不触发拉取及监听仅限本机。

### 桌面与界面

- 前端类型检查、生产打包、相关 lint，以及 Rust 测试／检查均完成并记录实际输出。
- 浏览器验证重做界面的空态、加载态、错误态、冻结状态、主题、键盘交互和窗口尺寸；模拟 UI 验证不能替代真实 Tauri 功能测试。
- Windows 验证托盘隐藏／恢复、单实例、停止释放端口、自启开关注册／取消。
- 实际生成便携 ZIP 与 NSIS 安装包，核对版本、包内文件和运行方式识别。便携版从不同工作目录启动时仍使用 exe 同目录的 `data/`；覆盖升级和整体移动目录后，订阅配置及快照保留。
- 在隔离的 Windows 测试环境验证安装、覆盖升级与卸载：升级保留数据和本地链接，卸载遵守用户的数据保留选择，自启项不指向已删除的安装路径。使用测试安装路径与虚构订阅数据，保留用户在用安装及数据。
- 安装器显示路径选择页；分别验证自定义目录、其他盘符、中文／空格路径与不可写目录。确认升级恢复上次路径，快捷方式、卸载和自启均指向实际安装位置，配置与快照仍保存在用户数据目录。
- 验证便携版与安装版同时启动时不会同时运行两个服务，且不会读取或覆盖另一种分发方式的数据。
- 用户提供真实订阅后，再验证 Clash Verge 实际导入与请求刷新；实际重启登录后的自启验证需要用户在设备上执行，不由单元测试或构建成功代替。
